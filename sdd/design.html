Design at Advanced Higher

Design turns the requirements specification into something a programmer can implement. From Higher you already know how to read and write structure diagrams and pseudocode showing top-level design, data flow and refinements, and how to sketch an interface with a wireframe. Advanced Higher keeps all three and adds a new notation designed specifically for object-oriented programs: the UML class diagram.

Design is the second-biggest skill in the course assessment: 20 marks of the project and 16–24 marks of the question paper.

Key Terms

Top-Level Design
The main steps of the program, numbered, before any detail is added.
Refinement
Breaking one top-level step into numbered sub-steps (3 → 3.1, 3.2, 3.3).
Data Flow
The variables and data structures passed in and out of each module.
Class Diagram
A UML diagram modelling the static structure of an OO program — class name, instance variables, methods, visibility and inheritance.
Instance Variable
A variable defined in a class, holding data belonging to each object — listed with its data type on a class diagram.
Visibility (+/−)
On a class diagram, + marks a public member and − marks a private member.
Constructor
The method that creates and initialises an object — shown in the methods section with the same name as the class.
Wireframe
A user-interface design showing visual layout, inputs, validation, underlying processes and outputs.

Structure Diagrams & Pseudocode

The notation is unchanged from Higher — what changes is the content being designed. Advanced Higher designs routinely involve 2D arrays, arrays of objects, and modules that connect to a database. You must be able to read and understand designs using structure diagrams, pseudocode and UML, and write efficient designs using pseudocode.

Example — pseudocode design with top-level design, data flow and refinement

Design for the stock search program analysed on the Analysis page (data held in a 2D array):

Top-level design with data flow
1. Read stock data from file into 2D array    # Data flow OUT: stock(2D array)
2. Sort array into ascending order of itemID  # IN: stock  OUT: stock
3. Get target itemID from user                # OUT: target
4. Search array for target                    # IN: stock, target  OUT: found, row
5. Display result                             # IN: found, row, stock
Refinement of step 4 (binary search)
4.1 set low to 0 and high to number of rows - 1
4.2 set found to false
4.3 while not found and low <= high
4.4    set mid to (low + high) DIV 2
4.5    if stock[mid][0] = target then
4.6       set found to true and row to mid
4.7    else if target > stock[mid][0] then
4.8       set low to mid + 1
4.9    else
4.10      set high to mid - 1
4.11   end if
4.12 end while

Notice each process from the functional requirements became a numbered top-level step, the data flow names the structures passed between modules, and the refinement expands one step into implementable detail — exactly the three things the course spec asks a design to show.

💡
Pseudocode is not a fixed notation — more "code-like" pseudocode is fine, and in the exam marks are for the logic, not the style. What loses marks is missing steps (forgetting to initialise, no loop end condition) or a design that doesn't match the requirements.

UML Class Diagrams

Where a use case diagram models the dynamic behaviour of a system, a class diagram models its static structure: the classes, what data they hold, what they can do, and how they relate to each other. This page assumes the OO vocabulary — if terms like method or inheritance feel shaky, skim the Object-Oriented Programming page first, then come back.

Anatomy of a class

A class is drawn as a box with three sections:

  1. Class name — at the top;
  2. Instance variables — each with its data type (address: String);
  3. Methods — including the constructor, which always has the same name as the class.

Every member is marked with its visibility: a − prefix for private (usable only by the owning class) and a + prefix for public (usable by any class).

Example — the House class (estate agency program)
House
−address: String
−town: String
−bedrooms: Integer
−description: String
−houseValue: Integer
+house()
+setAddress()
+getAddress()
+updateBedrooms()

All five instance variables are private (−), so they can only be reached through the public (+) methods. house() is the constructor — same name as the class — used to create each individual House object. setAddress() and getAddress() are a setter and getter (mutator and accessor): the methods that edit and retrieve the value of the private variable address.

Inheritance on a class diagram

A sub-class inherits all the properties and methods of its super-class. On a class diagram, inheritance is shown by an arrow pointing from the sub-class to the super-class.

Array of objects on a class diagram

An instance variable can itself be an array of objects of another class, written as:

Notation
offersReceived: Array of Offer[ ]

where Offer is another class. The connection between the array of objects and its class is also shown with an arrow.

Example — full class diagram for the estate agency

The full design has House as the super-class, with ForSale and ForRent as sub-classes (inheritance arrows point up to House). ForSale contains offersReceived: Array of Offer[ ], so a fourth class, Offer, is linked to ForSale by an arrow.

ForSale → HouseForRent → HouseOffer
−askingPrice: Real
−closingDate: String
−underOffer: Boolean
−offersReceived: Array of Offer[ ]
−sold: Boolean		 −rentalCost: Real
−deposit: Real
−rentalLength: Integer
−rented: Boolean		 −dateOfOffer: String
−amountOfOffer: Integer
+forSale()
+updateAskingPrice()
+updateSoldStatus()		 +forRent()
+updateRentStatus()		 +offer()
+setOfferDate()
+getOfferDate()
+setOfferAmount()
+getOfferAmount()

Because ForSale inherits from House, a ForSale object has all nine instance variables — the five from House plus its own four — without House's variables being re-declared. That is the whole point of inheritance: common data and methods are defined once, in the super-class.

⚠️
Checklist for drawing a class diagram in the exam: class name on top ✔ instance variables with data types ✔ visibility symbols on every member ✔ constructor named after the class ✔ inheritance arrow from sub-class to super-class ✔. Missing data types and missing +/− symbols are the two most common dropped marks.

User-Interface Design

At Higher a wireframe showed layout, inputs and outputs. At Advanced Higher a wireframe must indicate five things:

  • Visual layout — where every element sits on the screen;
  • Inputs — every value the user provides, and the control used to enter it;
  • Validation — annotated against each input: presence, range, length, restricted choice;
  • Underlying processes — what happens when each button is pressed ("clicking Search calls the binary search on the stock array");
  • Outputs — where and how results are displayed.
Example — annotating a wireframe

For the stock search program: a text box labelled itemID (annotation: "input — integer, range check 1000–9999"); a Search button (annotation: "underlying process — binary search of 2D array; displays row if found, error message if not"); an output area (annotation: "output — itemID, price, number in stock").

Test Yourself

Attempt each question first, then expand the marking instructions to check your answer.

Reading a Class Diagram — 3 marks

A class diagram shows the following class:

Class diagram (text form)
Member
-------------------------
−name: String
−email: String
−sessionsAttended: Integer
-------------------------
+member()
+getEmail()
−updateEmail()

(a) State the name of the constructor. (1 mark)
(b) Explain why getEmail() is needed to display a member's email address. (1 mark)
(c) State which method could not be called from the main program, justifying your answer. (1 mark)

Marking Instructions
  • (a) member() — the constructor always has the same name as the class. (1 mark)
  • (b) The instance variable email is private (−), so it cannot be accessed directly from outside the class — the public getter method returns its value. (1 mark)
  • (c) updateEmail() — it is marked private (−), so it can only be used by methods inside the Member class. (1 mark)
Inheritance on a Diagram — 2 marks

A veterinary program has a Animal class (instance variables: name, age, owner) and a Dog class (instance variables: breed, microchipNo) which inherits from Animal.

(a) State how the inheritance would be shown on a UML class diagram. (1 mark)
(b) State how many instance variables a Dog object has, justifying your answer. (1 mark)

Marking Instructions
  • (a) An arrow from the Dog (sub-)class pointing to the Animal (super-)class. (1 mark)
  • (b) Five — Dog inherits name, age and owner from Animal and adds breed and microchipNo. (1 mark)
