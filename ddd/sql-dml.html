Higher Recap — the DML You Already Have

Everything from Higher SQL is still live at Advanced Higher and can appear in any question: SELECT … FROM … WHERE with joins across three or more tables, wildcards (LIKE '%…%'), computed values with aliases (AS), the aggregate functions (MIN, MAX, AVG, SUM, COUNT), GROUP BY, ORDER BY, and INSERT, UPDATE and DELETE.

Advanced Higher adds three things, and the full clause order becomes:

SQL — the complete SELECT skeleton
SELECT   list of field names
FROM     list of table names
WHERE    condition
GROUP BY list of field names
HAVING   condition
ORDER BY list of field names;

All examples below use the travel agency database — and each one implements a design from the Query Design page.

Key Terms

HAVING
Filters grouped results — applied after GROUP BY, where WHERE cannot use aggregate functions.
Subquery
A query in brackets inside another query's WHERE clause — also called an inner or nested query.
NOT
Returns records where the condition is not true.
BETWEEN
Selects values within an inclusive range — numeric or text.
IN
Matches a value against a list — or against the rows returned by a subquery.
ANY
True if any of the subquery's values meets the condition.
EXISTS
True if the subquery returns one or more rows.

The HAVING Clause

The WHERE clause cannot be used with aggregate functions — WHERE COUNT(*) >= 2 is illegal, because WHERE is applied to individual records before any grouping happens. HAVING was added to SQL for exactly this reason: it filters the summarised, grouped results after GROUP BY has done its work. Using HAVING requires a GROUP BY to be present.

Resorts with at least two hotels (implements Query Design example 1)
SQL
SELECT resortName, COUNT(*) AS [Number of Hotels]
FROM Resort, Hotel
WHERE Resort.resortID = Hotel.resortID
GROUP BY resortName
HAVING COUNT(*) >= 2;

Read it in execution order: join the tables (WHERE matches the keys), group the rows by resort, count each group — then HAVING throws away groups with fewer than two hotels.

Big-spending customers, biggest first (implements example 2)
SQL
SELECT firstName, surname,
       SUM(pricePersonNight * numberNights * numberInParty)
           AS [Total cost of all Bookings]
FROM Customer, Booking, Hotel
WHERE Customer.customerNo = Booking.customerNo
  AND Booking.hotelRef = Hotel.hotelRef
GROUP BY firstName, surname
HAVING SUM(pricePersonNight * numberNights * numberInParty) >= 2000
ORDER BY SUM(pricePersonNight * numberNights * numberInParty) DESC;
💡
WHERE vs HAVING in one line: WHERE filters rows before grouping; HAVING filters groups after. A query can use both — WHERE to restrict which records get grouped, HAVING to restrict which groups appear.

The New Logical Operators

At National 5 you met AND and OR. Advanced Higher adds five specialist operators used with the comparison operators (=, <, >, <=, >=, LIKE) in the WHERE clause:

NOT

Returns records where the condition is not true:

SQL — non-coastal resorts and their hotels
SELECT resortName, resortType, hotelName, mealPlan
FROM Resort, Hotel
WHERE Resort.resortID = Hotel.resortID
  AND NOT resortType = "coastal";

BETWEEN

Selects values within an inclusive range — and it works on text as well as numbers:

SQL — customers in towns E through M, alphabetically
SELECT surname, postcode, town
FROM Customer
WHERE town BETWEEN "E" AND "M"
ORDER BY town;

BETWEEN also appears in HAVING: HAVING COUNT(*) BETWEEN 2 AND 4 — customers with between two and four bookings.

IN

Matches a value against a list — a tidy alternative to a chain of ORs:

SQL — hotels offering certain meal plans
SELECT hotelName, mealPlan
FROM Hotel
WHERE mealPlan IN ("Room Only", "Half Board", "Full Board");

NOT combines with IN to exclude a list: WHERE NOT resortType IN ("city", "country").

ANY and EXISTS only make sense with subqueries — they're covered below.

Subqueries in the WHERE Clause

A subquery (inner query) is a query embedded, in brackets, within the WHERE clause of another query (the main or outer query). The subquery executes first, and its results are passed to the main query as a condition. This is how you answer questions that need two steps of reasoning — "the most expensive", "below average", "never booked".

Single-value subqueries

The most expensive hotel (implements Query Design example 4)
SQL
SELECT hotelName, starRating, pricePersonNight
FROM Hotel
WHERE pricePersonNight =
    (SELECT MAX(pricePersonNight) FROM Hotel);

The inner query returns one value — the maximum price — which the main query then compares with =. The same shape answers "below-average star rating": AND starRating < (SELECT AVG(starRating) FROM Hotel).

Multiple-value subqueries — IN, ANY, EXISTS

A subquery that returns more than one row can only be used with the multiple-value operators:

IN — hotels booked by customer 315
SQL
SELECT hotelName, starRating
FROM Hotel
WHERE hotelName IN
    (SELECT hotelName FROM Hotel, Booking
     WHERE Hotel.hotelRef = Booking.hotelRef
       AND customerNo = 315);

Add NOT for the complement — resorts not booked by customer 315 (see the design on the Query Design page).

ANY — bookings costing more than any booking by certain customers
SQL
SELECT customerNo, Hotel.hotelRef,
       pricePersonNight*numberNights*numberInParty AS [Booking Cost]
FROM Booking, Hotel
WHERE Booking.hotelRef = Hotel.hotelRef
  AND pricePersonNight*numberNights*numberInParty > ANY
    (SELECT pricePersonNight*numberNights*numberInParty
     FROM Booking, Hotel, Customer
     WHERE Booking.hotelRef = Hotel.hotelRef
       AND Booking.customerNo = Customer.customerNo
       AND surname IN ("Danderhall", "Lowden", "Shawfair"));

> ANY is true if the value beats at least one of the subquery's values — i.e. anything greater than the smallest of them.

EXISTS / NOT EXISTS — customers who have never booked
SQL
SELECT firstName, surname, address
FROM Customer
WHERE NOT EXISTS
    (SELECT * FROM Booking
     WHERE Customer.customerNo = Booking.customerNo);

EXISTS returns a Boolean: TRUE if the subquery contains any rows, FALSE if it returns none. Here, for each customer, the subquery looks for that customer's bookings; NOT EXISTS keeps only the customers for whom none are found.

Rules subqueries must follow

  • Subqueries must be enclosed in brackets;
  • A subquery usually has only one field in its SELECT clause (unless used with EXISTS, where SELECT * is normal);
  • An ORDER BY cannot be used inside a subquery (the main query can have one);
  • A single-value operator (=, >, <) on a subquery that returns many rows causes an error — multiple-value subqueries need IN, ANY or EXISTS.

Test Yourself

Attempt each question first, then expand the marking instructions to check your answer. For full multi-part exam questions, head to SQL Practice Questions.

WHERE vs HAVING — 2 marks

A candidate writes:

SELECT resortName, AVG(pricePersonNight)
FROM Resort, Hotel
WHERE Resort.resortID = Hotel.resortID
  AND AVG(pricePersonNight) > 100
GROUP BY resortName;

The query produces an error. Identify the mistake and rewrite the faulty line correctly. (2 marks)

Marking Instructions
  • An aggregate function (AVG) cannot be used in the WHERE clause — WHERE applies to individual records before grouping. (1 mark)
  • Move the condition to a HAVING clause after GROUP BY: HAVING AVG(pricePersonNight) > 100; (1 mark)
Write a Subquery — 3 marks

Using the travel agency database, write a query to display the hotel name and price per person per night of every hotel that costs less than the average price per person per night. (3 marks)

Marking Instructions 
SELECT hotelName, pricePersonNight
FROM Hotel
WHERE pricePersonNight <
    (SELECT AVG(pricePersonNight) FROM Hotel);

Award 1 mark for the correct SELECT/FROM; 1 mark for the subquery calculating AVG(pricePersonNight); 1 mark for comparing with < in the WHERE clause.

Predict the Output — 2 marks

Explain what the following query displays:

SELECT resortName
FROM Resort
WHERE EXISTS
    (SELECT * FROM Hotel
     WHERE Hotel.resortID = Resort.resortID
       AND starRating = 5);

(2 marks)

Marking Instructions
  • For each resort, the subquery looks for hotels in that resort with a 5-star rating; EXISTS returns TRUE if at least one such row is found. (1 mark)
  • So the query displays the names of resorts that have at least one 5-star hotel. (1 mark)
