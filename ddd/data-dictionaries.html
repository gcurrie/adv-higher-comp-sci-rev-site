Higher Recap — What a Data Dictionary Does

A data dictionary defines the properties of every attribute in every entity of the design: entity name, attribute name, primary/foreign key, type, size, whether a value is required, and any validation (presence check, restricted choice, field length, range). None of that changes at Advanced Higher.

What changes is the type column. At Higher you wrote generic types: text, number, date, time, Boolean. At Advanced Higher, attribute types are expressed as SQL data types — because the data dictionary is now a direct blueprint for the CREATE TABLE statements you will write yourself:

  • text is now varchar;
  • number is split into int (whole numbers) and float (decimals);
  • date and time remain, with fixed SQL formats.

Key Terms

varchar(size)
Variable-length text; the size parameter is mandatory and restricts the maximum number of characters (0–65535).
int
Whole numbers. A size parameter is optional (it only restricts display width).
float(size, d)
Decimal numbers; size is the total number of digits, d the digits after the decimal point.
date
A calendar date in the format YYYY-MM-DD.
time
A time in the format hh:mm:ss.
Required
Whether a value must be present — becomes NOT NULL in the CREATE TABLE.
Validation
Presence check, restricted choice, field length or range — each maps onto an SQL constraint.

⚠️
Two classic slips: writing "text" or "number" in an Advanced Higher data dictionary (use the SQL types); and choosing int for a price or an average — anything with a decimal point needs float. Phone numbers and postcodes are varchar, not numbers: they have leading zeros and are never calculated with.

Test Yourself

Attempt each question first, then expand the marking instructions to check your answer.

Choosing Types — 3 marks

A cinema database stores, for each screening: the screening reference (e.g. "SCR047"), the ticket price (e.g. 12.50), and the start time (e.g. 19:45:00).

Complete the type and size columns of the data dictionary for these three attributes. (3 marks)

Marking Instructions
  • screeningRef — varchar(6): text with digits and letters, size mandatory. (1 mark)
  • ticketPrice — float(4,2) (or similar): a decimal value; int would lose the pence. (1 mark)
  • startTime — time: format hh:mm:ss. (1 mark)
Higher → Advanced Higher — 2 marks

A Higher candidate's data dictionary lists an attribute as: numberInStock — number — required.

Rewrite the type for an Advanced Higher data dictionary, and explain why "number" is no longer acceptable. (2 marks)

Marking Instructions
  • Type should be int (a whole-number count). (1 mark)
  • At Advanced Higher, attribute types are expressed as SQL data types, and "number" is split into int and float — the dictionary must state which, because it becomes the type in the CREATE TABLE statement. (1 mark)
